### Round 3 — Phase 1 only — 2026-08-14 — same reviewer resumed — **READY**

Zero blocking findings. Converged inside the three-round cap.

The round-2 blocker is resolved: the median is taken over non-zero-length edges, with
a stated 500 m fallback where that set is empty. The reviewer verified the fix's
load-bearing invariant independently rather than taking the changelog's word — that
§2.1's fifth error condition gives every edge two distinct endpoints, the tie-break
puts distinct stations in distinct cells, the minimum distance between two integer
lattice points is 1, and §2.4's occupancy rejection preserves one-station-per-cell at
every point cost is evaluated. So every post-snap edge is ≥ 1 cell and the numeric
hazard is confined to the pre-snap derivation. It confirmed the consequence that
follows: **a sixth error condition rejecting coincident stations would be wrong, not
merely unnecessary**, since the pipeline handles that input correctly.

It also re-derived the `eastbank` fix rather than accepting it — on the four-edge
trunk, `oldtown` and `eastbank` are both degree 2 with {Red, Green} on all three
incident trunk edges, so §2.5 collapses at neither and the segment between them
carries full offset at both ends. And it confirmed `central` still reaches degree 4
across 3 lines with the longer trunk.

Four non-blocking findings, all folded in:
- §2.1's shape excerpt was stale against the new four-edge trunk — updated to carry
  `eastbank`, with its note rewritten to record the deviation from the sources rather
  than claim verbatim fidelity to them.
- assertion 5's "valid SVG" for the one-station input needs `margin_cells` > 0, since
  the envelope reduces to `2 * margin_cells * units_per_cell` when `i_max = i_min` —
  `RenderParams::default()` now states `units_per_cell` = 40, `margin_cells` = 2,
  `stroke_width` = 6, with the reason on the margin.
- assertion 4's literal needs a tolerance, `g` being a product of `cos` and `sqrt` —
  now `1e-6` relative.
- phase size has grown since round 1, but the growth is specification rather than
  design, so it stays inside one plan-mode pass. No change.

**Numbers re-derived this round** (recorded so a later round can trust them): 17
stations and 3 lines are authored to OQ-5; the deduped edge count is hand-counted
from the JSON and explicitly not recomputed by the code under test; `g` is a
hand-computed literal plus an even-count unit test isolating the lower-middle rule;
500 m is a stated constant exercised by assertion 5; the 1 km–100 km bound on the
larger axis has an order of magnitude of margin either way, since §2.1's sample
coordinates give ~1.53 km station spacing and a 17-station network lands around

### Round 2 — Phase 1 only — 2026-08-14 — same reviewer resumed — **NOT READY**

All three round-1 blockers confirmed resolved. One new blocking finding, and it was
**introduced by the round-1 fix** — the case the loop's own guidance warns about.

**Blocker: the derived default `g` was undefined for a zero-edge network, which the
same round's new error contract had just declared legal.** §2.1 gained "a station
referenced by no line is legal", so `{"stations":[one],"lines":[]}` parses to a
1-node, 0-edge graph — and §2.2's default `g` was "the median projected length of all
graph edges", a median of the empty set. The natural implementation indexes out of
bounds. A second instance: two stations at identical coordinates give a zero-length
edge that can drive the median to 0, making `round(x / g)` a NaN that casts silently
to cell 0. Two sections written in one pass, each correct alone, contradicting each
other.

Resolved by taking the median over non-zero-length edges, adding an explicit 500 m
fallback where that set is empty, arguing why that constant escapes the section's own
argument against constants (a network with no non-degenerate edge has no typical edge
for a constant to be wrong about), and stating the invariant that confines the hazard
to the pre-snap plane. Gate assertion 5 was added to cover both degenerate inputs.

The reviewer answered both questions the changelog asked it directly. The 1 km–100 km
range is correct and catches a degrees-for-metres error by four orders of magnitude,
but **cannot** catch `cos(lat_c)` omitted from `x` — a 27% inflation that stays inside
the bounds. That limit is now recorded in the assertion itself. The derived `g` is
implementable and does not break Phase 6's field-enumeration test, since
`grid_spacing` has a flag and `null` in a `--params` file is equivalent to omitting
the flag.

Six non-blocking findings, all accepted. The most valuable was that **`oldtown` at
degree 2 gives Phase 5 a lens, not a parallel segment**: offsets collapse at
`central` (degree 4) and at `riverside` (line set changes), leaving one interior
station, so two paths pinch at both ends and separate only in the middle. The trunk
was lengthened to `riverside` → `oldtown` → `eastbank` → `central` → `market`, a
deliberate deviation from both source documents, settled at Phase 1 because that is
where the fixture is authored and discovering it at Phase 5 means re-authoring the
fixture every later gate is keyed to. Also: `g`'s value had no gate assertion at all
(added as assertion 4); assertion 5's range did not say which axis (now the larger);
the `2g` cluster threshold is degraded by a derived `g` (deferred to **OQ-7**,
blocking Phase 4); assertion 9 forward-referenced Phase 6's `--params` (folded into
assertion 10); and §2.2 gave the point transform but no document envelope (added).

### Round 1 — Phase 1 only — 2026-08-14 — fresh reviewer, repo access — **NOT READY**

**Round 0 — is this the right thing to build at all?** Yes, and asked once for this
episode. Phase 1's defining property is that it produces a real, viewable SVG — a
genuine if degraded instance of the observable §1 names — before any layout
intelligence exists, and the spec argues explicitly for taking the whole slice
because every smaller cut of it produces nothing anyone can see. The observable is
the right one: a schematic-map generator exists to produce a map a person looks at,
and the candidates rejected when the project adopted this methodology (the
`SchematicLayout` coordinates, the parameter structs, the Tauri app) are respectively
invisible, invisible, and a delivery vehicle. Caveat recorded rather than waved:
Phase 1's output is grid-snapped with zero iterations, so it is a recognizable
network rather than a transit poster — the same artifact degraded, not a different
artifact.

Three blocking findings, all one cluster: **the numeric chain lat/lon → projected
plane → grid cell → SVG user unit was pinned nowhere in the spec or in either source
document**, and Phase 1 is the phase that must build all of it.

1. **Units of the projected plane and the value and home of `g` were unspecified.**
   The only numeric hint was `--grid-spacing 20` in §1 — a Phase 6 flag — and it is
   meaningless without units: at the sample coordinates' ~1.5 km spacing, `g = 20`
   in metres makes collision impossible and `g = 20` in degrees puts the whole
   network in one cell. Resolved by pinning all three coordinate systems with
   formulae, denominating the plane in metres, and giving `g` a home as
   `LayoutParams::grid_spacing: Option<f64>` whose default derives from the network.
2. **The gate clause "including the tie-broken pair" asserted a fixture property the
   fixture spec did not require.** Off-grid is not colliding — so the clause was
   either unsatisfiable or vacuous, and in the vacuous reading the OQ-3 tie-break
   would ship with zero coverage in the one phase that builds it. Resolved by
   requiring a colliding pair in OQ-5 and splitting the assertion into two halves.
3. **The tie-break had no resolution order, breaking §2.4's determinism claim.**
   OQ-3's proposal fixed the spiral's order but never said which of two colliding
   stations keeps the cell. Resolved by claim order = input `stations` array order,
   first claim wins, and by the general rule that input order is the iteration order
   everywhere it is observable — which names the per-process `HashMap` seeding hazard
   the reviewer predicted. **The author found a second instance the reviewer did
   not**: §2.4's "move to whichever lowers `t` most" had the same hole for equal-cost
   candidate cells, now broken by the same spiral order. Phase 1 gained a
   cross-process byte-stability assertion, since two in-process calls cannot catch a
   per-process hasher seed.

Nine non-blocking findings, all accepted — including that `geometry.rs`'s segment
intersection and angle math had no Phase 1 consumer (moved to Phase 2, where `c1`
and `c5` are their first tests), that §2.1's own JSON example would fail validation
(labelled a shape excerpt; a five-condition error contract added), that the edge
count named no literal, and that the SVG y-flip was unstated.

**The round's best catch was verification of OQ-5, not a finding against it.** The
reviewer opened the third document the sources point at and confirmed independently
that the 17-station fixture exists nowhere — no station ids at all in the agent
research file — and that the pointer chain dead-ends without looping back. It also
corrected OQ-5's description of that chain, which the spec had slightly wrong while
reaching the right conclusion.
